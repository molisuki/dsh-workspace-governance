# 资产本体、候选分类与风险控制矩阵

## 1. 策略层权威与裁决权隔离

| 顺位 | 有效证据 | 违规处理 |
|---|---|---|
| 宿主 | 执行器的路径、权限、安全及保密边界 | `V01_SCOPE` → `STOP_OBJECT` |
| 任务 | 当前用户目标、授权范围、排除项 | 越界 → `V01_SCOPE` |
| 工程 | 实际生效的根与子域规则、架构及接口契约 | 不自行提升权限 |
| 状态 | 进程、事务、锁、用户数据、审计、恢复 | `V06_RUNTIME` / `V07_DATA` → `STOP_BATCH` |
| 证明 | 源码、静态/动态引用、消费者、回归和回退 | 未满足门禁 → `HOLD` |

操作符、违规码、验收状态、熔断效能均继承 [主契约](../SKILL.md#2-术语与操作契约)。`CANDIDATE` 不构成删除许可。

**编码与边界判定**：源码扫描采用严格 UTF-8 解码；非法字节记录 `coverage.errors[].code=invalid-utf8` 并置 `coverage.complete=false`，不得对受损文件输出可删除判定。SQLite `-journal`／`-wal`／`-shm` 属事务数据；任意层级 `runtime`、`.dsh-ops` 及其大小写变体均保护且不进入内容扫描；`AGENTS.md`、`VISION.md`、`README.md` 等治理文件及其大小写变体均按受保护对象处理。此规则仅限制发现器的扫描结论，不构成对数据文件的改写许可。
**开放候选类别**：`C01–C38` 是既有审计样式的追踪标识，不代表“只治理三十类对象”，亦非自动删除清单。新候选先登记其物理身份、正向失效证据、依赖消费者、存活性、数据保护与恢复能力；有足够证据后映射至既有操作裁决。新增正式 `C##` 分类需显式注册稳定语义及兼容测试；不得自行扩大 `DELETE` 的适用条件、混用 `CANDIDATE` 与最终裁决。


## 3. 变更许可反例

| 禁止推断或操作 | 违规码 → 熔断 |
|---|---|
| 依据命名、时间戳、忽略规则或零文本引用认定删除许可 | `V04_REFERENCE` → `STOP_OBJECT` |
| 合并时改变权限、事务、舍入、时序或兼容 | `V05_SEMANTICS` → `STOP_OBJECT` |
| 直接删除 WAL/SHM、活动日志、锁、租约 | `V06_RUNTIME` / `V07_DATA` → `STOP_BATCH` |
| 删除唯一备份、审计链或用户事实 | `V07_DATA` → `STOP_BATCH` |
| 跟随 junction、symlink、mount、submodule 越界 | `V01_SCOPE` → `STOP_OBJECT` |
| 使用过期 HEAD、扫描报告、测试回执 | `V02_SNAPSHOT` → `REBASELINE` |
| 以治理严重度代替真实写入权限 | `V01_SCOPE` → `STOP_OBJECT` |
| 覆盖他人未提交工作或通配 Git 清理 | `V03_PROTECTED` → `STOP_OBJECT` |
| 发现器有遗漏仍宣称全库清零 | `V09_COVERAGE` → `STOP_ACCEPTANCE` |

适用验收缺失记 `UNKNOWN`，有可核查的不适用证据记 `NA`；不允许把未执行检查写成 `PASS`。

## 4. 风险样例与适配控制

下表仅为主规范第 2 章 `R0–R4` 的场景映射，不重定义级别。

| 场景 | 基础风险 | 调整因子与适用验证 |
|---|---|---|
| 可再生的孤立构建产物 | `R0` | 确认无发布、租约与外部消费者；核验再生 |
| 无副作用纯函数整合 | `R1` | 消费者重绑定、输出及异常等价 |
| 多源技术规范合并 | `R2` | 术语本体、规范原子、链接及信息架构审计 |
| 桌面入口与动态资源退役 | `R3` | 打包、URL、权限隔离及负向路由 |
| 身份存储、事务日志、跨租户资产 | `R4` | 对象级许可、原生数据协议、恢复演练及审计保全 |

风险上调由不可逆性、共享影响、动态依赖或证据不确定性触发；发现器只定位候选，不直接改变风险等级或目标文件。

## 5. 资产本体与候选语义等价类

资产登记采用 \`Asset = (identity, class, ownership, lifecycle, consumers, semantic_contract, preservation, recovery)\`。逻辑类型用于取证编排，不创建新的主控制状态或扫描器机器枚举。

| 本体维度 | 类型分类 | 判别条件 | 消费者检查 |
|---|---|---|---|
| 存在形式 | 源码、对象文件、目录、符号、远端标识 | 物理实例与逻辑名称可定位 | 别名、硬链接、符号引用与版本 |
| 作用角色 | 权威源、派生投影、运行缓存、恢复副本 | 唯一职责和再生能力可观察 | 下游读取、写入和恢复依赖 |
| 生命周期 | 当前使用、条件使用、疑似失效、历史留存 | 当前构建与时间范围具证据 | 条件编译、定时执行及旧客户端 |
| 权属关系 | 用户、工作区、服务、第三方、共享租户 | 实际权限与合同可核 | 跨仓库、跨进程和跨账户消费 |
| 变更影响 | 局部、跨模块、运行时、不可逆 | 必需风险维度可区分 | 事务一致性、可用性和故障恢复 |
| 信息性质 | 事实、义务、配置、执行数据、审计证据 | 价值及保留时限有来源 | 历史审计、迁移和回放机制 |

**候选选择策略**：按作用域、实际正证据、依赖闭合程度及预期收益排列审查优先级；审查优先级不得转换为物理执行优先级。已受保护对象仍应登记为保全项，不能因用户请求全量治理而消失于统计分母。新增未知类型先归于对应上位本体，再依真实消费者与运行机制寻找适配方案。

### 5.1 重复与失效的判别逻辑

| 证据机制 | 足以触发调查 | 实际退役还需要 |
|---|---|---|
| 名称相似 | 两个模块、文档或配置同名近义 | 同一责任、相同生效域及全消费者覆盖 |
| 静态零引用 | 当前扫描工具未发现直接引用 | 动态、外部、条件与历史使用均已核验 |
| 长期未变更 | 时间戳及提交历史显示未修改 | 证明失去业务合同或已安全迁移 |
| 编译未纳入 | 单个构建配置未包含资产 | 全平台、feature 和发布变体枚举 |
| 重复输出 | 局部正向输入下结果相等 | 边界、异常、权限、副作用及精度等价 |
| 生成产物 | 路径符合已知生成目录 | 生成器可用、消费者和发布保留已闭合 |
| 历史说明 | 注释或文档描述已迁移版本 | 当前数据兼容、法规及审计义务已失效 |
| 无现行测试 | 测试集合没有覆盖该对象 | 外部接口无消费者且业务义务已退出 |

**反向证明**：实际处置之前，应寻找至少一种仍使该对象有效的输入、平台、配置、用户、时间窗口或故障恢复路径。反证成立时保留实体或先迁移消费者；反证未发现仅表示当前受测集合内未命中，不能证明开放世界不存在。

## 6. 候选聚合与职责边界

### 6.1 同源聚合

不同发现器可能对同一真实对象生成多个候选。聚合时需建立物理身份、逻辑标识、路径别名、版本和消费者关系，先合并**指向同一实体**的冗余记录，再针对独立义务分别裁决。对具有不同所有权、挂载边界或数据保留要求的相似名称，不允许仅按字符串合并。

### 6.2 依赖反转与职责漂移

源模块和目标模块之间的消费者迁移应同时审查接口方向、初始化顺序、错误处理、权限、审计、性能及资源释放。形成循环依赖、引入隐式全局状态或改变异常传播均属于实质行为差异，不因新文件数减少而自动通过。技术规范合并须对主体、操作、条件、例外、量词和负面限制建立原子级映射。

### 6.3 优先级与维护收益

收益至少从**运行冗余、维护传播范围、权威冲突、故障面、构建负担及文档可追溯性**中选择实际可量化或可证伪指标。没有实测性能或构建体量时，不得编造节约百分比。对既有有效的边界层、兼容适配器及安全验证，不得仅因代码简短而裁定属于无独立职责的冗余适配层。

## 7. 风险闭包与验证配置

| 风险因子 | 证据来源 | 需要追加的验证 | 撤销条件 |
|---|---|---|---|
| 外部消费 | 运行入口、插件宿主、远端 API、发布清单 | 实际消费者演练、旧版本兼容 | 消费者未知 |
| 并行共享 | Git 状态、进程、锁、租约及维护计划 | 冲突检测、版本栅栏与隔离 | 状态不唯一 |
| 不可逆性 | 数据所有权、备份及回滚机制 | 恢复演练、幂等性及负向安全 | 恢复仅为文字承诺 |
| 语义迁移 | 源目标条件与异常 | 双向原子映射、边界与差异回归 | 有效义务遗失 |
| 规模与波及面 | 当前部署、集成面和变更对象数 | 分阶段发布、限定批次、可观察回滚 | 单次操作超越已授权范围 |
| 证据不足 | 扫描错误、未读取资源和过期报告 | 重新取证、复核和实测 | 将未知计为通过 |

风险配置只要求在实际适用域追加验证，不重复改变主规范 \`R0–R4\` 的定义。安全拒绝以受影响对象为粒度，不阻断尚未涉及失效门禁的独立只读分析。

## 8. 权威收敛与发布治理

同一规范问题应存在单一权威正文、清晰消费者及生效版本。派生摘要和索引可复用结论，但不得形成与主定义竞争的第二套义务。迁移时先建立新权威、修复引用与类型，再确认旧规范不再承载独有义务、例外或历史保留责任；随后才考虑删除旧文件。

实际完成标准为：候选真实身份已登记、有效正证据与保护因素均已裁决、全部适用门禁已通过、实际消费者迁移完成、物理实体变更有回执、残留反向审计覆盖已声明范围、用户与第三方数据保全、版本新鲜度一致。仅文档改名、文本压缩、目录美化不属于工业资产退役的完整证明。
