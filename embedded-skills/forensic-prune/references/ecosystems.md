# 运行生态、数据协议与跨平台验证
**扩展说明**：矩阵记录已具名生态与当前发现器的覆盖方式，既不是所有编程语言、系统架构与数据载体的完整集合，也不授权清理未列对象。陌生生态须先查明可执行入口、依赖解析、动态消费者、持久数据、锁、备份、版本和原生恢复机制，再执行 [主 Skill](../SKILL.md) 的 `G0–G7` 门禁；扫描无法观测的依赖记为 `UNKNOWN`，相关清理裁决为 `HOLD`。`V01_SCOPE–V12_AUDIT` 与 `PASS/FAIL/NA/UNKNOWN` 是固定协议，不随生态扩展自发新增。

**扫描保护规则**：任意目录深度的 `runtime/`、`.dsh-ops/` 均禁止只读发现器向内遍历，记录为 `PROTECTED`、`coverage.skipped`；任意深度的 `.git/`、`node_modules/` 不向内遍历且仅依据当前发现器的定义域计算覆盖。扫描成功不等于外部进程空闲、事务已终结或全部第三方消费者已枚举。

## 3. 文件系统与平台边界

| 平台 | 物理事实 |
|---|---|
| Windows | junction/reparse point、ACL、保留设备名、长路径、大小写、文件句柄 |
| Linux/POSIX | symlink、mount、bind mount、inode/hardlink、socket/FIFO、ACL |
| macOS | APFS clone、Bundle、codesign、LaunchAgent、symlink |
| 云/网络目录 | 同步冲突、共享挂载、远端租约、对象所有权、控制器 |

跨路径、数据所有权、事务或恢复协议不明：`UNKNOWN`；按 [主契约](../SKILL.md#2-术语与操作契约) 触发 `V01_SCOPE`、`V06_RUNTIME` 或 `V07_DATA`。

## 4. 验收适配

| 事实 | 验收状态 |
|---|---|
| 已运行并通过，证据对应现行快照 | `PASS` |
| 已运行且失败 | `FAIL` → `V11_VALIDATION` → `RECOVER` |
| 有可核查不适用依据 | `NA` |
| 未运行、工具缺失、访问失败、输出过期、覆盖不足 | `UNKNOWN` |

验证按受影响面执行：源码解析 → 类型/静态检查 → 构建/链接 → 单元 → 集成 → 端到端 → 历史兼容 → 并发事务 → 恢复与审计；未执行的适用层级不得作为完成证据。

## 5. 技术适配器输入与输出

本文件仅描述领域技术检查点。跨技术栈变更仍采用主规范的 `G0–G7`、`S00–S10` 和固定验收状态；不能通过语言特有机制新增裁决权限。

| 适配阶段 | 最小输入 | 输出证据 |
|---|---|---|
| 入口解析 | 包清单、动态注册、脚本、依赖注入、条件编译、发布构建 | 实际可达入口与调用消费者 |
| 运行隔离 | 数据库事务、进程、文件句柄、租约、用户工作区 | 保护对象与安全实施窗口 |
| 实体操作 | 真实文件对象、大小写、链接、权限、路径及内容摘要 | 精确修改、物理缺席与目录清理证明 |
| 行为验证 | 项目原生构建、测试、集成服务、恢复工具 | 当前版本退出码、行为、权限与恢复结果 |
| 残留验证 | 入口、配置、包、路由、脚本、文档与外部消费者 | 不存在性、无悬空引用或明确未决列表 |

对不支持原子删除/移动的文件系统，缩小事务范围并采用可验证的阶段提交。删除不是介质安全擦除，禁止通过覆写审计日志、移除 Git 元数据或强制终止活动会话伪造完成证明。

## 6. 运行语义与技术能力模型

生态适配器采用 \`Adapter = (entrypoints, consumers, build_variants, state_ownership, runtime_protocol, recovery_protocol, verification)\`。适配器负责**从领域实现提取必要证据**，不拥有对象最终处置权。不存在对应系统或工具时，输出“不适用且有证据”或 \`UNKNOWN\`，不得因为本矩阵包含某工具就安装或执行。

| 能力域 | 必需事实 | 技术依赖 | 缺失后的操作限制 |
|---|---|---|---|
| 入口图 | 公开 API、模块导出、启动、事件注册、插件发现 | 真实源码及构建配置 | 禁止以静态引用零命中作删除依据 |
| 产物图 | 源生成、打包、签名、发布和缓存生命周期 | 构建工具、产物清单、CDN | 不能将发布工件推断为可安全重新生成的冗余资产 |
| 状态图 | 进程、文件句柄、服务租约、数据事务 | OS 或服务端合法查询 | 不推断运行资源闲置 |
| 数据图 | 写入权威、持久化、复制与恢复 | 数据管理原生接口 | 不允许普通文件清理绕过协议 |
| 兼容图 | API、ABI、格式迁移、旧客户端及平台组合 | 已有消费者合同 | 不以新版本通过替代旧版兼容 |
| 保护图 | 用户、第三方、历史、法定与供应链资产 | 项目治理及所有权证据 | 禁止物理动作超出真实许可 |
| 验证图 | 当前版本构建、负向回归、恢复演练 | 实际工具回执及环境 | 只报告已执行的测试范围 |

## 7. 文件系统与跨平台同一性

### 7.1 路径、对象和符号关系

路径字符串不能完全代表物理对象身份。对大小写不敏感文件系统、Unicode 正规化、保留设备名、junction、symlink、硬链接、挂载、网络路径和分离式工作树，应在授权范围内取得真实对象类型及链接指向。路径重命名、别名替换和挂载重新定位会使旧版身份判定失效。

| 竞争关系 | 必需核验 | 非法路径变换 |
|---|---|---|
| 逻辑路径与真实路径 | 实际工作区根、目标对象类型、链接边界 | 仅用字符串前缀判定安全 |
| 同名不同实体 | 文件标识、大小写规则及作用域 | 将近似名称映射为用户目标 |
| 多路径单实体 | 硬链接数量、共享消费者 | 移除一个路径即当作所有数据消失 |
| 挂载和工作树 | 真实所属仓库及独立生命周期 | 递归进入未知权限资源 |
| 特殊文件 | FIFO、socket、设备和重解析点 | 使用普通删除机制处理 |
| 同步与远端 | 网络租约、上传状态、版本冲突 | 本地缺席推导远端已删除 |

### 7.2 Git 状态与版本治理

Git 的 HEAD、index、工作树、未跟踪、未忽略和另一个 worktree 都可能包含不同的事实与保留责任。只读发现器报告 Git 不可用不能证明工作区无未提交改动；detached HEAD 应登记实际提交而非伪造分支名称。stash、子模块、sparse checkout、LFS 或外部工作树需要按实际支持度分别取证，不能自动归入扫描完成。

**不可接受操作**：无具体目标的 \`reset --hard\`、\`clean -fdx\`、直接删除 Git 元数据、强制解锁、删除仍被运行进程持有的文件、覆盖其他会话修改以及通过清除验证日志掩盖失败。这些禁止行为不是单纯的代码风格偏好，而是保全与授权门禁的具体体现。

## 8. 数据存储、事务和外部服务的原生边界

### 8.1 数据所有权和恢复

| 系统类别 | 特有约束 | 可接受的验证 |
|---|---|---|
| 关系数据库 | 事务隔离、WAL/redo/binlog、主从、迁移顺序 | 原生事务与一致性恢复 |
| 键值与文档存储 | TTL、压缩、索引构建、最终一致性 | 读取可见性、消费者与重建 |
| 消息队列 | offset、保留期、重放、消费者组、幂等 | 租户、消费位置和可回放性 |
| 对象存储 | 版本化、删除标记、生命周期、签名 URL | 当前与历史版本的权限及恢复 |
| 文件同步 | 冲突副本、离线编辑、重试与最终同步 | 双向版本状态、异常恢复 |
| 模型及数据集 | 权重、许可、校验、血缘、推理服务 | 使用依赖、可重建性及访问控制 |

数据库侧写文件与运行日志不应由普通临时文件清理替代原生生命周期操作。生产环境中的“清空缓存”“清理历史”可能影响有效事务、计费、备份、模型状态及合规义务，必须依据现行合同判定。

### 8.2 外部平台与部署边界

CI/CD、包注册表、应用商店、镜像仓库、CDN、任务调度、基础设施状态和 SaaS 插件宿主构成可能的外部消费者。退役一个本地入口前应检查有效发布变体、正在运行实例、缓存生效期、版本兼容、租户和拥有者。没有实际外部访问或部署回执时不能宣称远端生效。

### 8.3 异常与补偿策略

外部资源删除可能异步完成或产生删除标记；操作返回成功并不等于所有消费者立即不可访问。应区别请求已受理、状态已提交、数据已持久化、远端已可见及恢复已验证。超时且副作用未知时先查询实际现态，不盲重试非幂等操作。

## 9. 验证矩阵与风险控制

| 验证维度 | 最小测试 | 高影响扩展 | 不能证明 |
|---|---|---|---|
| 结构 | 文件、权限、Schema、引用、清单 | 跨语言与跨版本解析 | 行为等价 |
| 静态行为 | 类型、符号、构建、链接及注入 | 条件编译与多变体入口 | 动态消费不存在 |
| 运行功能 | 适用单元、集成与异常回归 | 历史数据兼容、故障注入及负向安全 | 未来所有环境正确 |
| 事务 | 竞争读写、取消、超时和恢复 | 部分失败、幂等、补偿失效 | 仅一次成功即永不失败 |
| 外部消费 | API、发布、路由及客户端可见性 | 回滚、兼容迁移、租户和缓存 | 完整枚举未知第三方 |
| 审计保全 | 真实操作、恢复数据与历史证据 | 法定追溯、独立核查 | 合规认证自动取得 |

风险分级由主规范 \`R0–R4\` 定义。此矩阵只决定适用技术栈的测试深度，未取得实际环境时保持验证状态 \`UNKNOWN\`，不以构建工具是否可安装作为删除许可。

## 10. 发现器能力与盲区治理

\`scripts/inventory.mjs\` 支持指定根目录、JSON/文本格式及文件数限额的只读枚举，并对部分历史注释、生成路径和文件类别产生调查线索；不执行 AST 全语言分析、真正的构建图解析、远端权限查询、数据事务隔离、删除、合并或恢复。

| 实际观察 | 可以输出 | 必须限定 |
|---|---|---|
| 扫描目录并记录文件 | 观察到的对象和候选类型 | 被排除目录与读取失败 |
| Git 状态读取成功 | 当前提交、分支及工作区记录数 | 无法取得索引细节的限制 |
| 来源文件异常 | 文件路径、错误码和覆盖失败 | 不得仅凭现有证据判定允许删除 |
| 生成资产目录命中 | 调查建议与路径 | 不得推定可安全再生 |
| 受保护文件命中 | 保护信号与不遍历策略 | 不得将保留理解为永久不可变 |
| 文件数限额命中 | 限额和未观测清单 | \`coverage.complete=false\` |
| 候选排序稳定 | 在相同输入条件下可复验顺序 | 不代表候选正确性或完整性 |

## 11. 适配完成与变更管控

适配器完成条件为：指定环境的真实入口可定位，运行与数据保护边界得到满足，操作通过主合同门禁，验证回执与当前版本一致，残留反向检查覆盖所声明范围。缺少关键消费者或平台证据时仅形成受限结论，不将技术矩阵的规范性覆盖冒充实际工具实现。

新技术栈引入时优先复用上位能力域和现有主合同；只有已形成独立可验证差异的技术约束才增设专有适配说明，不为扩展篇幅增加无功能条款。
