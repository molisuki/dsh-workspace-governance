# 规范术语、权威类型与状态约束

## 1. 唯一术语系统

本文件拥有**规范操作符、语义状态、严重度解释及术语冲突裁决**的唯一权威。源项目已有定义时，须优先保留其命名空间和真实效力。本 Skill 的诊断词汇不自动变为目标项目规则。

| 概念 | 规范标识 | 定义域 | 违例判据 |
|---|---|---|---|
| 强制义务 | `MUST` | 指定条件下的必要动作 | 由许可或建议无源升级 |
| 禁止义务 | `MUST_NOT` | 指定条件下的不可执行动作 | 禁止对象或作用域漂移 |
| 明确许可 | `MAY` | 非强制的授权动作 | 许可扩大为未知对象 |
| 非强制建议 | `RECOMMEND` | 不作为硬门禁的建议 | 直接触发强制断路 |
| 条件 | `IF` | 规范前提与触发谓词 | 必要/充分互换 |
| 结果 | `THEN` | 满足条件后的合法效果 | 编造未实现的副作用 |
| 生效域 | `SCOPE` | 对象、时点、版本、角色与资源 | 局部规则跨域应用 |
| 规范原子 | `ATOM` | 可独立审查的一个语义单位 | 竞争义务合并为同一身份 |
| 权威词典 | `GLOSSARY` | 定义、别名、来源和生效版本 | 无权威多义合并 |
| 通过/失败 | `PASS/FAIL` | 实际指定的检查集合 | 用结构检查宣称语义认证 |
| 验收阻断 | `BLOCK` | 拒绝受影响交付或结果声明 | 冒称系统级中断或删除 |
| 恢复复验 | `RECHECK` | 缺陷修复后重做受影响检查 | 未取得新证据直接标成功 |
| 证据 | `EVIDENCE` | 可定位的观测、依据或审查材料 | 自报状态代替外部回执 |
| 处置依据 | `REMOVAL_BASIS` | 经核查的等价或失效来源 | 按外观或旧文件名删除 |

术语的大小写、字段名与协议字符串属于受保护载荷。普通正文可压缩描述，但不能修改引用方依赖的机器标识。

## 2. 逻辑算子与义务强度

| 输入语义 | 规范表达 | 关键不变量 |
|---|---|---|
| 条件成立时必须执行 | `P→MUST(X)` | P 的作用域及 X 的对象不变 |
| 仅以条件为前提允许执行 | `X→P` | 不反转为 `P→X` |
| 不存在例外时必须执行 | `¬E→MUST(X)` | 例外 E 的有效条件不变 |
| 对整个集合均适用 | `∀x∈S:P(x)` | S 的定义域与空集解释不变 |
| 至少一个满足 | `∃x∈S:P(x)` | 不扩大为所有对象 |
| 范围不包含端点 | `x<N` | 不擅加等号 |
| 包含端点 | `x≤N` | 不擅删等号 |
| 许可但非必要 | `MAY(X)` | 不转换为 `MUST(X)` |
| 责任主体差异 | `Actor(A)≠Actor(B)` | 不因同一操作名消除责任 |

符号是审阅表达，不表示系统已实现逻辑定理证明器。出现多重否定、反事实、条件与义务嵌套时，优先保留原表达的逻辑结构或标记 `UNRESOLVED`，不能为提高可读性损失正确性。

## 3. 缺陷严重度与外部契约隔离

| 诊断类 | 典型影响 | 受影响交付控制 | 恢复依据 |
|---|---|---|---|
| `S0_FATAL` | 关键义务遗失、越权动作、不可逆语义失真、结构合同破坏 | 阻断受影响发布及完成声明 | 原子映射、恢复证据及回归 |
| `S1_CRITICAL` | 关键失败路径缺失、权限歧义、规则无法执行 | 隔离缺陷对象、停止相关验收 | 对应门禁重新通过 |
| `S2_HIGH` | 权威重复、版本竞争、重大证据缺口 | 限制相关交付范围 | 来源、目标及依赖追踪 |
| `S3_MAJOR` | 非关键独立功能缺陷 | 明确缺陷及专项修复 | 局部可复现测试 |
| `S4_MINOR` | 不改变语义或可解析性的表达瑕疵 | 文案校订及格式检查 | 定位差异审查 |
| `S5_TRACE` | 辅助追踪信息不足 | 补足记录，不推导错误行为 | 证据补录 |

以上为**诊断分类**，不是目标项目已批准的 `S0–S5` 等级。遇外部已定义严重度，以其权威、作用域及版本为准；只有明确授权才能修改外部缺陷级别。结构导致解析改变时，不得误分类为纯外观问题。

## 4. 生命周期规范权威

生命周期的正式阶段与出入口唯一以 [SKILL.md](../SKILL.md) 为准：`DISCOVERED/ATOMIZED/NORMALIZED/REWRITTEN/VERIFIED/RELEASED/BLOCKED`。本文件仅解释**状态效力**，不复制第二套转换图。

| 状态组 | 允许的结论 | 不得声明 |
|---|---|---|
| 来源与解析阶段 | 已取得可定位来源及规范清单 | 已证明目标语义等价 |
| 规范化及重写阶段 | 已完成登记范围内的内容变换 | 已执行人工复核或外部发布 |
| `VERIFIED` | 当前快照具有指定门禁的实际证据 | 对未来版本及未知语义作保证 |
| `RELEASED` | 当前版本实际成果按载体交付 | 已自动修改宿主/其他 Skill |
| `BLOCKED` | 具体依赖义务及失败证据明确 | 在必要条件未恢复时宣称完成 |

`BLOCK` 为动作，`BLOCKED` 为状态，`FAIL` 为一次检查结果，`RECHECK` 为复验动作；不得因词形相近混用。

## 5. 术语一致性与迁移门禁

规范名称登记 `(canonical_name, meaning, type, domain, scope, aliases, authority, revision)`。只有在实际定义域、操作效果和异常分支相等时允许多对一合并；同词异义拆分命名空间。状态、枚举、默认值、阈值、单位、文件路径与 API 字段属于封闭合同，变更需正式来源及消费者兼容验收。

**双向一致性**：来源名称全部映射目标概念，目标新增规范全部有来源或批准的独立变化。未解决的冲突保留 `UNRESOLVED` 并阻断受影响完成声明。

## 6. 判定、处置与恢复的责任链

每个硬规则应能回答四项：`Precondition`（适用前提）、`Assertion`（可观察应然）、`Violation`（可复核不符合）、`Recovery`（修正及复验）。当目标系统没有自动断路能力时，处置仅定义为**拒绝验收或停止相关发布**，不宣称运行时故障恢复服务已经存在。

术语治理的完成证据包含权威词典、引用消费者、变更差异、状态/枚举校验与未决清单；词频减少或文字相似度不构成语义等价证明。
