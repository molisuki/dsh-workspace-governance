# 审计证据、机器门禁与验证层级

## 1. 证据权威与证明分层

本文件定义**审计 JSON、执行器真实能力、门禁检查范围及复验依据**。语义原子及双向映射由 [来源原子](atomization.md) 定义；状态与规范效力由 [主合同](../SKILL.md) 定义；本文件不创建新的并行状态机。

| 层级 | 可自动核验 | 独立审查对象 | 不支持的推导 |
|---|---|---|---|
| `SOURCE` | 文件 SHA-256、编码、实际读取与标识 | 来源权威、范围及隐含依赖 | 未读取材料不存在 |
| `STRUCTURE` | frontmatter、围栏、表格、相对链接及清单 | 渲染方言和动态引用 | 所有解析器一致 |
| `TRACE` | `A###`、源/目标非空内容行、引文与决策 | 原子枚举完备、跨段作用域 | 语义绝对等价 |
| `REVIEW` | 审核字段、UTC 时间、证据引用存在 | 审核行为、来源真实性与双向蕴涵 | 审核身份已认证 |
| `DELIVERY` | 包内字节、文件存在、最终哈希 | 外部状态、用户可达性与授权 | 产物已部署或永久有效 |

审计通过声明必须包括被检对象、当前版本、实际测试和未证明域；任何材料缺失只降低可声明范围，不以“专家模式”或标准名称代替证据。

## 2. 机器审计数据合同

机器数据唯一权威：[audit.schema.json](../assets/audit.schema.json)。核心结构为 `source_id/target_id/scope/source_sha256/target_sha256/units/unmapped_source/unauthorized_additions/open_issues/review`。`units` 包含 `id/kind/source_lines/source_quote/target_quote/decision/rationale` 及有条件的 `removal_evidence`。

| 字段域 | 通过条件 | 拒绝条件 |
|---|---|---|
| 来源与目标 | 身份及 SHA-256 与同一读取快照一致 | 哈希过期、对象竞争 |
| `scope` | `FULL/SELECTION/HEADING_RANGE/MULTI_FILE` | 擅自增加机器枚举 |
| `units` | 非空、唯一 `A###`、逐行源引文完整 | 重复 ID、行号越界、源内容冒领 |
| `decision` | Schema 中已定义值及对应证据 | `UNRESOLVED` 冒充完成 |
| 未映射项 | 双向内容行与相应单元可核验 | 来源或目标非空行无定位 |
| 审查记录 | 三类审查状态、审阅者、有效 UTC 时间及证据引用 | 重复键、非法类型、虚构审查结果 |

**解析安全**：输入 JSON 中重复对象键、NaN/Infinity、错误类型、非法枚举和缺失必需字段均拒绝；脚本只能验证记录形式及已实现的一致性约束，不证明审核人员确实完成了语义审查。

## 3. 执行工具与退出状态

在当前 Skill 根目录使用 Python 3.9+ 标准库：

`python -B scripts/verify_package.py .`

`python -B -m unittest discover -s tests -v`

| 退出码 | 语义 | 允许报告 | 必需处理 |
|---|---|---|---|
| `0/PASS` | 已实现的结构与来源内容清单检查通过 | 具体已检查项和版本 | 另核对语义及实际权限 |
| `1/FAIL` | 结构、映射、字段或已定义门禁违反 | 具体缺陷与已通过子集 | 依据错误码定位并复测 |
| `2/USAGE` | 参数、依赖、路径或解析环境错误 | 实际运行条件未满足 | 修复输入/目标并重新执行 |

**副作用隔离**：`refactor_gate.py` 只读取源、目标与审计文件；可写的报告必须指定独立有效目标，且不得覆盖输入及其符号链接/硬链接别名。报告使用同目录暂存与原子替换；运行失败不得破坏原报告。`verify_package.py` 不执行被检查材料中的任何命令，不获取外部事实。

## 4. 核心质量门禁

| Gate | 验收维度 | 不可接受状态 |
|---|---|---|
| `V01` | 源版本一致性 | 来源 Hash 与实际读取不一致 |
| `V02` | 目标版本一致性 | 目标 Hash 与实际读取不一致 |
| `V03` | 来源原子登记 | 独立义务缺失，或已登记行无有效映射 |
| `V04` | 删除依据 | 缺等价、失效、保留义务审查 |
| `V05` | 目标新增约束 | 新增义务或权限缺来源 |
| `V06` | 规范符号一致 | 操作符、类型、默认值或阈值漂移 |
| `V07` | 结构完整性 | Markdown、frontmatter、链接或清单无效 |
| `V08` | 生效作用域 | 时间、对象、主体、量词、例外变更 |
| `V09` | 拒绝与恢复 | 失败条件无实际断路对象或复验 |
| `V10` | 审计证据 | 缺定位、复现或审查范围 |
| `V11` | 交付载体 | 不符合已指定输出方式或文件不可访问 |
| `V12` | 验证新鲜度 | 源或依赖更新后沿用旧回执 |

Gate ID 为**审查维度**，不属于 `audit.schema.json` 的枚举扩展；脚本实现的缺陷码以脚本实际返回为准，不伪造自动实现覆盖。

## 5. 规模化取证与版本失效

分批处理时，必须登记每一来源的字节快照、有效范围及剩余材料；跨批次检查术语统一、逻辑条件、引用及保留锚点。独立审核可使用有限来源批次，但不能将局部通过升级为全库通过。

重构完成后冻结目标版本；任何文件、脚本或审计字段的后续修改都可能导致相应验证失效，应重新计算受影响的 Hash 和回归范围。

## 6. 结果记录与真实性

有效验收记录至少包括 `artifact_id, revision, scope, validation_method, actual_result, evidence_ref, limitations, reviewer_context`。缺少实际测试输出时为未运行或证据不足，不标记通过。机器结果与独立语义审核采用不同字段或不同报告段，不能共享未注明含义的 `PASS`。

## 7. 审计结果发布条件

只有来源范围已冻结、结构门禁通过、原子正反向映射经实际审查、核心缺陷得到闭合且输出可访问时，才可就**该版本、该作用域**作出完成声明；未获得可审计的人工审阅材料时仅报告已自动核验子集。
